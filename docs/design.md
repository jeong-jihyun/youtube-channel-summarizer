# youtube-channel-summarizer 설계

대상 채널: CONNECT AI LAB (https://www.youtube.com/@CONNECT-AI-LAB) — 설정에서 바꿀 수 있게 한다.

## 한눈에 보기

매일 정해진 시간에 Claude 예약 작업이 아래 순서로 돈다.

```
[1] 채널 영상 목록 읽기 (클라우드 크롬)
[2] 구글 시트 '영상목록'과 비교 → 아직 안 한 영상 5개 고르기
[3] 영상마다 자막 가져오기 → 요약 → 분류 정하기
[4] 영상마다 모의 프로젝트 1개 개발 (총 5개)
[5] GitHub에 반영 + 구글 시트 기록
[6] 끝나면 카카오톡으로 알림
```

## 1. 영상 목록과 자막을 가져와 요약

- 목록: 채널의 "동영상" 탭을 최신순으로 읽어 제목·길이·올린 날짜·영상 ID를 얻는다.
- 자막: 영상 화면의 자막(스크립트) 창에서 읽는다. 자막이 없거나 회원 전용 영상은 `건너뜀`으로 기록하고 다음 영상으로 넘어간다.
- 요약: 영상 1개당 `summaries/<영상ID>.md` 1개. 내용은 한 줄 요약, 핵심 5줄, 챕터별 메모, 따라 해 볼 점.
- 자막 원문 전체는 저장소에 넣지 않는다. 요약과 출처 링크만 남긴다.

## 2. 체계적인 분류와 리소스 관리

분류 코드(처음 8개, 시트 '분류' 탭에서 추가·수정):

| 코드 | 이름 | 예 |
|---|---|---|
| computer-use | 컴퓨터·스마트폰 유즈 | 화면 보고 대신 조작 |
| automation | 업무·콘텐츠 자동화 | 블로그·영상 자동 발행 |
| web-dev | 웹·앱 개발 | React, 디자인 → 코드 |
| local-ai | 로컬 AI | 내 PC에서 모델 실행 |
| robot-rl | 로봇·강화학습 | 시뮬레이션 |
| business | 1인 기업·수익화 | 사례·운영 |
| ai-news | AI 소식·정리 | 모델 소개 |
| etc | 기타 | |

분류 방법: 영상 제목·요약의 키워드를 '분류' 탭 규칙과 맞춰 가장 많이 맞은 분류 1개를 정한다. 애매하면 `etc`.

저장소 폴더 구조:

```
youtube-channel-summarizer/
├─ README.md
├─ docs/design.md            이 문서
├─ config/settings.json      채널 주소, 하루 개수(5), 시트 ID
├─ summaries/<영상ID>.md     영상별 요약
└─ projects/<분류코드>/<번호>-<이름>/   모의 프로젝트 (분류별로 묶음)
   ├─ README.md              어떤 영상에서 왔는지, 실행 방법
   └─ 소스 파일
```

- 프로젝트 번호는 `0001`부터 전체 통번호. 같은 영상으로 중복 생성하지 않는다(영상 ID로 확인).

## 3. 매일 5개 — 모의 프로젝트 개발

- 하루에 영상 5개 → 모의 프로젝트 5개. 영상 1개당 프로젝트 1개.
- 프로젝트는 영상 주제를 작게 흉내 낸 "동작하는 데모"로 만든다(수십 분 안에 끝나는 크기). 반드시 실행해 보고 `README.md`에 실행 결과를 적는다.
- 영상 337개를 5개씩 처리하면 약 68일이 걸린다. 최신 영상부터 거꾸로 진행한다.
- 5개 중 일부가 실패하면 성공한 것만 반영하고, 실패는 시트에 `실패`와 이유를 적는다. 다음 날 다시 시도한다.

## 4. 구글 시트로 반영 소스 관리

시트 1개, 탭 4개. 모두 단순한 표로 둔다.

| 탭 | 열 |
|---|---|
| 영상목록 | 영상ID, 제목, 올린날, 분류, 상태(대기/완료/건너뜀/실패), 요약 경로 |
| 프로젝트 | 번호, 날짜, 영상ID, 분류, 프로젝트명, 폴더 경로, 상태, 커밋 |
| 분류 | 코드, 이름, 키워드 |
| 실행기록 | 날짜, 시도, 성공, 실패, 비고 |

- 날짜별 반영 내용은 '프로젝트' 탭에서 분류로 묶어 한눈에 본다.

## 5. 카카오톡 알림

- 하루 작업이 끝나면 나와의 채팅으로 보낸다. 내용 예: `오늘 5개 중 4개 완료, 1개 실패 / 링크`.
- 크게 막혔을 때(채널 접속 불가, 시트 쓰기 실패)도 같은 방법으로 알린다.

## 확정한 결정

1. GitHub 반영(push): 매일 자동으로 올리고, 끝나면 카카오톡으로 결과를 알린다.
2. 블로그(jeong-jihyun.github.io): 하루에 요약 글 1개만 올린다(5개를 한 글로 묶음).
3. 실행 시간: 매일 새벽 5시(한국 시간).
