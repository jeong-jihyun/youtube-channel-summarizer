# 0009 AI 브라우저 루틴 설계기 (육하원칙 지시문·겹침 점검·모델 연결 비용)

- 제목: AI에게 네이버 블로그 맡겼습니다 | 설치부터 자동 발행까지 왕초보 무료 강의 (24분 17초, 조회 11만)

## 영상이 알려 준 것(핵심)
- AI 브라우저 'Aside'에 AI를 연결하면 브라우저를 대신 쓰는 직원을 둔 것과 같다. 모델 연결은 무료 크레딧(약 500) / 구독 로그인(ChatGPT·Claude·Grok) / API 키(Gemini는 구독 연결이 안 된다고 설명) / 로컬 AI(성능 한계) 네 가지.
- 일 잘 시키기: AI에 이름을 주고, 육하원칙(언제·어디서·어떻게…)으로 번호 단계의 '매뉴얼'을 쓰고, 공통 키워드의 참/거짓을 판단시키고, 마지막에 홍보 문구를 넣는다. 그 지시문을 '루틴'으로 등록하면 매일 오전 8시에 돈다.
- 저장은 초안 저장(사람이 확인 후 발행) vs 자동 발행. 설명란은 처음에 초안으로 시험하고 사실관계·저작권·사이트 정책을 확인하라고 한다. 시험 중 같은 루틴이 겹쳐 하나를 삭제했다.

## 무엇을 만들었나
`routine_planner.py` 의 `api()` 가 다음을 만든다.
1. 입력(이름·목표·시각·사이트·단계·홍보 문구·저장 방식)으로 붙여 넣을 지시문을 만들고, 빠진 칸(누가·왜·언제·어디서·어떻게, 사실 확인 단계 없음, '어디서'에 쓴 사이트가 단계에 안 나옴)을 알려 준다.
2. 초안/자동 발행 점검표(자동이면 영상 설명란의 주의 3가지).
3. 등록된 루틴 목록과 새 루틴의 겹침(같은 시각·같은 게시처, 60분 이내 같은 게시처, 같은 시각 다른 작업).
4. 모델 연결 비교: 가진 구독으로 연결 가능한지, API 종량제 월 비용(월 횟수 x 토큰 x 단가 x 사고 수준 배율), 월 20달러 요금제와의 비교, 로컬 AI 가능 여부, 추천 한 줄.

## 실제 실행 결과(실제 실행)
- 기본 예시(Brown, 매일 8시, X·네이버·구글→네이버 블로그, 초안): 영상의 4단계 지시문이 그대로 만들어지고 빠진 칸 없음. 기존 목록의 08:00 루틴 2개가 같은 게시처에서 겹친다고 경고(영상의 중복 장면과 같은 상황).
- 비용 계산 예: 월 30회 x 15만 토큰 x 100만 토큰당 5달러 = 22.50달러 -> 월 20달러 요금제가 2.50달러 더 싸다고 비교. 같은 입력에서 10만 토큰이면 15달러이며 환율 1,400원이면 21,000원(시험으로 계산식 확인).
- Gemini 구독만 있으면 구독 연결을 추천하지 않고 API 키 안내가 나오는 것을 확인.
- 자동 시험 13개 통과.

## 한계(미확인)
- Aside의 기능·요금은 영상 시점 설명이며 실제 설치와 실행은 하지 못했다. 영상은 약 500 크레딧이라고만 말했고 1회 실행의 크레딧 소모량은 알 수 없어 계산하지 않았다.
- 토큰 사용량, 단가, 환율, 사고 수준 배율(낮음 0.6, 중간 1, 높음 1.8, 최대 3)은 모두 내 가정이다. 월 20달러는 영상에 나온 Aside 요금제 값이다.
- 자동 발행은 플랫폼 정책과 사실 오류 위험이 있다. 이 도구는 글을 대신 발행하지 않는다.

## 이렇게 활용할 수 있어요
- 하고 싶은 자동화(블로그 글, 뉴스 정리 등)의 목표·시각·사이트·단계만 넣으면 영상 방식의 육하원칙 지시문을 만들고 빠진 칸을 알려 준다.
- 초안 저장과 자동 발행 중 무엇으로 시작할지 정하고, 영상 설명란의 주의(사실관계·저작권·이용정책)를 점검표로 확인한다.
- 이미 등록한 루틴 목록과 새 루틴의 시각·게시처가 겹치는지 먼저 보고 중복 발행을 막는다.
- 가진 AI 구독(Claude/ChatGPT/Grok/Gemini)과 월 실행 횟수로 구독 연결, API 키, 월 20달러 요금제 중 무엇이 싼지 가정값으로 비교한다.

## 모바일(휴대폰)에서 바로 쓰기
https://jeong-jihyun.github.io/lab/ 를 열고 'AI 브라우저 루틴 설계기(육하원칙 지시문·겹침 점검·모델 연결 비용)' 카드를 눌러 값을 바꾼 뒤 **실행**을 누른다. 서버가 필요 없고, 처음 실행은 파이썬을 내려받느라 10~20초 걸린다.

## 내 컴퓨터에서 시험·실행
```
make test      # 자동 시험 (python3 -m unittest -v test_project)
make run       # 웹 화면 실행 -> http://localhost:8000 (PORT=9000 make run 으로 포트 변경)
```
- 파이썬 코드에서 직접 부르기: `from routine_planner import api; api({...})`
- 다른 프로그램에서 부르기: `GET http://localhost:8000/api/run?키=값` (JSON 응답), 상태 확인은 `/health`

## 배포
```
make docker    # 컨테이너로 빌드·실행 (http://localhost:8000)
```
Dockerfile 이 있으므로 Render·Fly.io·Cloud Run 등 컨테이너를 받는 곳에 그대로 올릴 수 있다. 자세한 순서는 저장소의 docs/GUIDE.md 참고.
