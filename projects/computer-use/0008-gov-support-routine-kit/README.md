# 0008 정부지원사업 AI 직원 루틴 키트 (프롬프트·공고 판정·서류·루틴표)

## 영상이 알려 준 것(핵심)
- 스마트폰 AI 비서(앱 '피클')에 정부과제 탐색·지원, 쿠팡 리뷰, 장려금 확인을 맡기는 시연. 진행자는 하루에 정부과제 3건(1억원짜리 2건, 수천만원 1건)을 지원했다고 말한다.
- 정부과제 프롬프트는 '찾을 지원 종류 + 확인할 출처(정부24, K-스타트업, 기업마당) + 공식 공고 확인 + 내 사업 정보(업종, 지역, 나이, 개인/법인/예비/재창업, 창업 시점)'로 구성한다.
- 지원 종류는 사무·인건비·대출. 접수 서류는 사업자등록증, 국세 완납, 지방세 완납, 등기부, 경력.
- 루틴 = 시각을 정해 매일 반복(오전 10시 정부과제, 11시 이메일, 12시 유튜브 스튜디오 예). 본인인증·서류 발급·최종 확인은 사람이 한다. 걱정되면 정보를 적게 주고 대화부터 시작하라고 조언한다.

## 무엇을 만들었나
`gov_kit.py` 의 `api()` 가 아래 5가지를 한 번에 만든다.
1. AI 비서에 붙여 넣을 프롬프트. '정보 공개 수준'(최소/보통/상세)에 따라 넣는 개인정보를 조절한다(영상의 보안 조언 반영).
2. 사용자가 AI가 찾아 온 공고를 `제목|종류|마감일|최대업력|지역|지원금|대상` 한 줄씩 붙여 넣으면 마감 지남·대상 불일치·지역 불일치·업력 초과를 제외하고, 나머지를 후보/보류로 나눠 마감 임박(3일 이내)을 표시한다.
3. 접수 서류 5종 중 이미 준비한 것과 필요한 것 계산.
4. 사람이 꼭 해야 하는 3가지(본인인증, 서류 발급, 제출 전 최종 확인).
5. 시간대별 루틴표와 같은 시각 겹침 점검.

## 실제 실행 결과(실제 실행)
- 예시(인천 법인, 창업 2025-12-15, 업력 0.9년, 기준일 2026-11-12, 공고 6개): 후보 2개(마감 D-2 인건비 지원, 지역이 맞는 사무공간 지원), 보류 1개(업력 조건 없는 대출 공고는 원문 확인), 제외 3개(대상 예비창업자 전용, 개인 전용, 마감 지남).
- 정보 공개 수준이 '최소'면 사업자 형태·지역·나이가 프롬프트에 들어가지 않고, '상세'일 때만 나이가 들어가는 것을 확인.
- 자동 시험 14개 통과(업력 계산, 마감 당일/지남, 업력 한도 초과, 지역·대상 불일치, 예비창업자, 잘못된 줄 보고, 공개 수준별 프롬프트, 서류 개수, 입력 오류, 루틴 겹침).

## 한계(미확인)
- 영상의 앱 '피클', 정부과제 3건 지원 결과, 선정 가능성은 검증하지 못했다. 이 도구는 AI에게 시킬 문장과 선별 기준을 만들 뿐 실제 공고를 가져오거나 접수하지 않는다.
- 공고 판정(업력·지역·대상 비교, 후보 점수, 임박 3일)은 내가 정한 경험칙이다. 실제 자격은 공고 원문이 우선이다. 서류 5종은 영상에서 말한 목록이며 공고마다 다르다. 등기부가 개인사업자에게 필요한지는 공고마다 달라 '확인'으로만 표시한다.
- 비밀번호·로그인 정보를 AI에 넘기는 위험은 이 도구가 해결하지 않는다.

## 이렇게 활용할 수 있어요
- 내 업종·지역·업력만 넣으면 영상의 정부과제 프롬프트(출처·공식 공고 확인·내 정보)를 AI 비서에 바로 붙여 넣을 형태로 만든다.
- AI가 찾아 온 공고를 한 줄씩 붙여 넣으면 마감·대상·지역·업력 조건으로 후보/보류/제외를 가르고 마감 임박을 알려 준다.
- 접수 서류 5종 중 아직 못 챙긴 것과 사람이 직접 해야 하는 본인인증·발급·최종 확인을 한눈에 본다.
- 개인정보가 걱정되면 정보 공개 수준을 '최소'로 바꿔 정보 없이 시작하는 프롬프트를 만들고, 시간대별 루틴표로 하루 자동화를 설계한다.

## 내 컴퓨터에서 시험·실행
```
make test      # 자동 시험 (python3 -m unittest -v test_project)
make run       # 웹 화면 실행 -> http://localhost:8000 (PORT=9000 make run 으로 포트 변경)
```
- 파이썬 코드에서 직접 부르기: `from gov_kit import api; api({...})`
- 다른 프로그램에서 부르기: `GET http://localhost:8000/api/run?키=값` (JSON 응답), 상태 확인은 `/health`

## 배포
```
make docker    # 컨테이너로 빌드·실행 (http://localhost:8000)
```
Dockerfile 이 있으므로 Render·Fly.io·Cloud Run 등 컨테이너를 받는 곳에 그대로 올릴 수 있다. 자세한 순서는 저장소의 docs/GUIDE.md 참고.
